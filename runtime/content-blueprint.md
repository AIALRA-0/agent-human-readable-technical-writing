# 内容骨架与覆盖矩阵

## 1. 目标

内容骨架决定原文信息放在哪里、补充解释插在哪里以及读者按照什么顺序最容易理解；这一阶段不进行全文润色

## 2. 段落合同

每个 `SegmentContract` 至少说明：

- 读者任务：本段帮助读者判断或完成什么
- 源语义单元：本段必须覆盖哪些原文内容
- 背景和推断：本段允许加入哪些补充内容
- 必须表达：哪些结论必须出现
- 禁止表达：哪些未经支持的结论不能出现
- 推荐顺序：本段按照什么关系展开

## 3. 覆盖矩阵

覆盖矩阵为每个内容单元记录类型、是否必须保留、目标段落和当前状态；源语义单元全部分配以前不能进入成文

表格组件先保留表头、列、行、单元格、顺序和原始值，再在表格外说明整体用途，并逐列说明名称、单位、允许值或内容范围和实际作用；解释列不能替代原表结构

两个以上承担相同作用的定义、步骤、比较对象、事实、原因或动作建立 `parallel_groups`；表格的表头、行、单元格和顺序属于 TABLE 组件结构，不作为散文排比组项目；需要 `indented_list` 时，每个独立项目必须使用对应层级的标准 Markdown 列表标记，单纯换行或空格缩进不算列表；每组登记全部项目、自然类别和缩进深度，是否出现冒号不影响登记

代码组件为每个有效语句建立 `CODE` 单元；采用代码注释时记录注释位置，采用外部解释时记录逐行说明位置，连续概述不能代替单元映射；可修复的同行注释不属于可执行源代码，局部调整注释不能改变代码语句、字面值、调用关系或控制条件；针对可配置或可迭代输入，次数、上限和失败边界必须绑定默认值或输入长度；有 n 个输入值时分别记录最多调用 n 次与最多重试 n-1 次，空输入必须记录零调用边界；正文复述源代码字面量时将实际值或表达式放入行内代码；调用次数、重试次数和空输入边界不得用中文分号压在同一列表项中；代码语言和标识符在正文中使用行内代码，代码语言名称不自动成为专业术语；用户参考中的受保护标识逐字保留

采用代码注释时，每个代码块独立计算最长可注释代码行；所有有效语句的合法注释保持同行并从同一列开始，空行、纯闭合符和结构性括号不参与计算；不能合法添加注释的格式使用逐行解释

## 4. 内容充分性

成文前确定当前内容属于教程、操作、参考、解释、决策、状态、审计或项目变化，并登记读者必须理解、看到、决定和验证的内容

复杂内容最多分为三层：首层回答当前结果、未知和决定；第二层展示结构、路径和证据摘要；第三层保存命令、文件、摘要值和完整审计记录

完成、风险、限制和重要说明分别绑定对应证据；证据缺失、冲突或过期时显示真实状态，不能用笼统的自动通过覆盖多个主张

交付前执行删除测试：删除一个句子、标签、卡片、图例或统计以后，如果读者的理解、判断、行动、证据边界和下一步都不改变，就删除该内容或移入更深一层

## 5. 通过条件

- 所有源语义单元已经分配
- 每项补充解释具有明确理解目的
- 没有段落只承担装饰作用
- 补充背景没有抢占原文主线
- 必要条件没有只放在脚注或表格中
- 同一信息没有机械重复
- 排比组全部使用缩进列表并覆盖所有登记项目
- 代码单元全部具有合法注释或独立可定位的逐行解释
- 注释代码的全部可注释单元保持同行并从最长代码行之后的同一列开始
- 读者完成当前任务所需的理解、事实、决定和验证已经覆盖
- 每个重要主张具有独立证据或明确未知状态
