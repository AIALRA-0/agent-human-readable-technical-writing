# 内容骨架与覆盖矩阵

## 1. 目标

内容骨架决定原文信息放在哪里、补充解释插在哪里以及读者按照什么顺序最容易理解；这一阶段不进行全文润色

## 2. 段落合同

每个 `SegmentContract` 至少说明：

- 读者任务：本段帮助读者判断或完成什么
- 源语义单元：本段必须覆盖哪些原文内容
- 背景和推断：本段允许加入哪些补充内容
- 必须表达：哪些结论必须出现
- 禁止表达：哪些未经支持的结论不能出现
- 推荐顺序：本段按照什么关系展开

## 3. 覆盖矩阵

覆盖矩阵为每个内容单元记录类型、是否必须保留、目标段落和当前状态；源语义单元全部分配以前不能进入成文

两个以上承担相同作用的定义、步骤、比较对象、事实、原因或动作建立 `parallel_groups`；每组登记全部项目、自然类别和缩进深度，是否出现冒号不影响登记

代码组件为每个有效语句建立 `CODE` 单元；采用代码注释时记录注释位置，采用外部解释时记录逐行说明位置，连续概述不能代替单元映射

## 4. 通过条件

- 所有源语义单元已经分配
- 每项补充解释具有明确理解目的
- 没有段落只承担装饰作用
- 补充背景没有抢占原文主线
- 必要条件没有只放在脚注或表格中
- 同一信息没有机械重复
- 排比组全部使用缩进列表并覆盖所有登记项目
- 代码单元全部具有合法注释或独立可定位的逐行解释
