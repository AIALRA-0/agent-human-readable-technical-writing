# 规则等级与执行边界

## 1. 目的

规则等级用于区分能够由代码确认的问题、需要语境判断的问题、本次任务明确要求和普通风格建议；系统不得把主观偏好伪装成确定性事实

## 2. 四级规则

### 2.1. `MACHINE_FINAL`

代码能够确定，失败时直接阻断；适用于受保护数字、路径、代码标识、JSON 结构、标题编号和术语登记中的精确形式

### 2.2. `MACHINE_CANDIDATE`

代码只能发现疑似问题，Agent 必须根据上下文确认、判定误报或请求用户决定；适用于可能重复、可能缺少解释、可能过长和可能存在术语泄漏

### 2.3. `PROFILE_REQUIRED`

当前任务、内容组件或用户配置明确要求，失败时按照本次契约阻断；适用于 Lucas 标点、图片元素覆盖、表格逐格覆盖和代码解释颗粒度

### 2.4. `ADVISORY`

用于优化语气、节奏和普通叙述顺序，不能单独阻断；用户明确拒绝后可以通过真实案例升级为配置要求，但不能自动升级成通用规则

## 3. 禁止的通用硬门

以下检测不得作为普遍硬错误：

- 出现某个普通词语
- 句子超过固定长度
- 采用某种常见语序
- 没有使用统一章节模板
- 没有为每个术语机械填满同一组解释字段
- 正则表达式判断全文自然度不足

## 4. 永久硬约束

以下问题始终阻断：

- 因果方向改变
- 条件和结果互换
- 可能性升级成已确认事实
- 建议升级成强制要求
- 原文信息未经授权删除
- 外部背景伪装成原作者主张
- 没有来源的内容作为事实加入

这些约束的语义核对不能伪装成纯代码绝对证明；系统通过来源映射、覆盖记录、候选判断和用户验收降低风险
