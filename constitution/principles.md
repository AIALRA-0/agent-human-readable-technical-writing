# vNext 1.1 基本原则

本文件规定可验证写作系统不能偏离的基本思想；任何 Agent 修改本仓库以前都必须完整读取本文件

## 1. 源信息优先

改写、翻译和解释性扩写必须保留原文事实、关系、条件、否定、范围、数值与语气强度；任何补充解释都不能用于掩盖源信息丢失

## 2. 内容完整优先

改写和翻译不能只保留大意；每一项承担信息作用的原文内容都必须进入源语义单元，并在成文以前分配到明确段落

## 3. 允许解释增量

系统可以补充目标读者理解原文所需的背景、定义、机制、例子和关系说明；补充规模由解释增量等级决定

## 4. 来源必须分层

每项内容必须属于以下来源之一：

- `SOURCE`：原文直接表达的内容
- `USER_SUPPLIED`：用户在当前任务中提供的事实或要求
- `EXTERNAL_BACKGROUND`：为了帮助理解而加入，并且具有来源的外部背景
- `INFERENCE`：根据已登记内容推导出的解释，并且保留推断强度

外部背景和推断不能伪装成原作者主张

## 5. 结构先于表达

系统先完成原文理解、内容覆盖和关系确认，再生成目标风格正文；禁止通过多轮全文改写追求流畅，因为重复生成会扩大事实漂移风险

## 6. 风格不等于真理

语气、句长、段落方式和普通叙述顺序主要属于建议；系统不得把常见词语、固定句长或单一章节结构设为普遍硬门

## 7. 确定性问题代码化

能够准确判断的编号、数值、路径、机器标识、结构和登记术语由程序检查；依赖语境的问题只能标记为候选，由 Agent 或用户判断

## 8. 修复采用最小补丁

一个词错误时只修改这个词；一个段落错误时只修改这个段落；低一级范围能够修复时，不允许扩大到更大范围，默认禁止重新生成全文

## 9. 外部 Agent 不是正式依赖

外部 Agent 可以用于开发比较、影子评测和发现未知失败模式；正式运行不能依赖外部 Agent 才能完成

## 10. 不确定时停止推断

不同解释会改变事实、范围、结论或输出规模时，系统必须进入一次性问答确认；系统不能为了得到顺畅文本而自行选择最方便的解释

## 11. 用户验收是最终标准

脚本通过和模型评分不能替代用户是否真正愿意阅读；模型生成的案例只能进入候选区，只有用户明确接受后才能进入金标区

## 12. 零先验解释

图片、表格、代码和陌生技术内容默认按照第一次接触的读者处理；解释必须覆盖理解所需的对象、关系、输入、结果与证据边界

## 13. 实施停止条件

第一批 12 个锚点案例完成以后，候选版本必须停在人工审核节点；用户审核以前不得把案例标记为金标，不得根据候选样本宣布用户偏好已经满足，也不得安装为正式版本
