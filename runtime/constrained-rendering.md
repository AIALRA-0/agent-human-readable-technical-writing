# 受约束成文

## 1. 目标

受约束成文直接根据任务契约、内容骨架和用户配置生成目标风格正文；系统不先生成一个粗糙版本再进行多轮全文改写

## 2. 允许调整

- 中文措辞、句子长度和段落节奏
- 标题、列表和术语解释方式
- 正式程度和口语程度
- 图片、表格、代码和公式的呈现方式
- 当前用户配置中的标点和阅读习惯

## 3. 禁止调整

- 源语义单元
- 原文条件、否定、范围和结论强度
- 背景信息的来源类型
- 已确认的逻辑依赖
- 用户没有授权的新结论

## 4. 来源呈现

原文和补充说明可以通过就近解释、前置背景或独立补充说明自然结合；读者必须能够分辨哪些是原文主张，哪些是理解原文所需的外部背景或推断

任务合同要求同时展示原始材料时，按照材料类型选择呈现方式：

- 短篇逐字文本使用引用块
- 代码和日志使用对应语言的代码块
- 图片和表格保留原始对象
- 长篇原文进入独立原始材料小节

引用块只表示逐字来源或证据；生成结论、摘要和普通强调不得使用引用块

## 5. 主体与段落

独立动作、主体切换和可能产生歧义的位置明确主体；同一段落连续讨论一个明确主体时允许自然省略，禁止为了通过检查而机械重复主体

不同主题或块级结构之间使用一个空行；同一列表和嵌套列表内部保持连续，连续两个以上空行属于确定性错误

短停顿和紧密衔接使用逗号；较长并列、对比或需要明显分隔的内容使用分号；标点选择属于语境优化，不设置数量阈值

## 6. 媒介与居中

图片、表格、Mermaid 和题注默认共同居中；GitHub 图片使用居中 HTML 图片容器，表格使用可访问的居中 HTML 表格，Mermaid 保留原生代码块并使用独立居中 HTML 题注

GitHub 候选必须在 1280 像素与 390 像素、亮色与暗色主题中检查对象位置、题注位置和横向溢出；只有实际页面全部通过才能声明居中完成

## 7. 句子支持

最终正文中的每个有效句子建立 `SupportMap`；无法指向源语义、用户补充、背景来源、推断关系、组件解释或必要过渡的句子进入删除候选

代码采用注释路径时，每个代码块先计算最长可注释代码行，再把全部合法同行注释放到最长代码之后的同一列；对齐可以增加行宽，不能把注释移到下一行；JSON 等不能合法添加注释的格式使用逐行解释

## 8. 专业名词

独立阅读单元中的专业名词首次出现时说明正式中文、官方英文、正式缩写、中文定义、名称含义、当前作用和实际影响；翻译任务默认保留专业名词的官方英文名称

官方形式具有最高优先级；`npm`、`Node.js`、`iOS`、`macOS` 和 `scikit-learn` 等名称不能为了统一外观而改写；`CI` 和 `HTTP` 等缩写保持登记形式；`npm` 不展开成 `Node.js Package Manager`

代码块、行内代码、网址、路径和逐字引用保持原始字符；这些内容不参加正文大小写修正

登记表没有提供术语形式时先核对官方来源；官方写法仍无法确认时停止生成该形式并返回 `REVIEW_REQUIRED`

## 9. 排比与多轮要求

两个以上承担相同作用的定义、步骤、比较对象、事实、原因或动作换行并缩进；嵌套并列继续增加一级缩进；压缩任务减少重复措辞，同时保留主题边界和必要换行

追加要求替换旧要求后，最终正文只保留当前有效内容；只有用户要求变更历史、撤销说明，或者法律、审计与证据核对需要时，才保留失效要求
