## 执行顺序

### 0. 关闭中断现场

1. 核对没有 Q49 进程
2. 原样保留 Q49 私有运行目录
3. 记录资格编号、摘要、计划数、已调度数、原子完成数和中断原因
4. 在公开开发账本中只保存脱敏摘要
5. 标记 Q49 不可恢复、不计入人工轮次、不计入用户接受
6. 不修改任何既有 Gold 或 Rejected

### 1. 第二轮正式资格

使用新资格编号运行 FWD-R2-021 至 FWD-R2-040，共 60 项

固定条件：

- 模型为 `gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna`
- 并发数为 3
- reasoning effort 为 `medium`
- 使用独立 `CODEX_HOME` 和独立任务目录
- 使用 `--ignore-user-config`、禁用搜索和无关工具
- 启用一次宿主错误重试和正式运行 `fail-fast`
- 首轮语义复核后在同一会话执行一次完整性补扫
- 最多三轮最小补丁
- 每项完成后立即持久化公开摘要和私有事件

恢复条件：只有公开结果、私有报告、资格编号、Skill 摘要、闭环运行器摘要和 `PASS` 项目集合全部一致时，才允许补缺失项

失败条件：`REVIEW_REQUIRED` 保持终态，第二次宿主错误保持失败，语义失败不能通过重复采样覆盖，代码或 Skill 变化后必须使用新资格编号

### 2. 生命周期和人工审核包

60 项全部通过以后：

1. 物化 60 个 Candidate
2. 预检并终结临时人工审核源
3. 删除临时源前确认正式账本写入成功
4. 生成四批审核包，每批 5 个案例，每个案例展示三个模型
5. 核对 Candidate、答案摘要、闭环证据和审核包一一对应
6. 更新 README、审计和计数
7. 在第一批审核包处停止，等待用户决定

物化后的最低计数为 Gold 32、Rejected 35、Candidate 60、总计 127

### 3. 人工审核循环

- 用户明确接受才复制为 Gold
- 用户明确拒绝才写入 Rejected
- 拒绝记录保存原因、正确部分和回归要求
- 只为被拒绝的模型生成下一人工修订号
- 已接受模型不得重跑
- 自动检查和模型投票不得写入 `approved_by_user`
- 第二轮首次成绩最高为 15/20，历史成绩永久保留
- 所有第二轮模型链没有待处理 Candidate 后，才允许下一轮

### 4. 连续完美轮次

每个新轮次生成 20 个全新案例和 60 个三模型闭环结果

每轮必须覆盖五档长度、五类受众、七类内容任务、主要组件、八类语气、分散条件、冲突来源、冗余材料、多轮覆盖、数字归属、否定与例外和跨章节术语

全局拒绝重复 `topic_id`、来源摘要和核心术语集合

任一模型拒绝即使该案例失败，任一案例失败即该轮不是完美轮次，连续完美计数归零

连续两个全新轮次达到三模型共同 `20/20` 后，人工发布门槛才算满足

### 5. 发布矩阵

人工门槛满足并冻结最终 Skill 树后，运行：

- 72 个触发边界案例乘三个模型，共 216 项
- 8 个长上下文案例乘三个模型，共 24 项

每项沿用同一闭环协议，公开结果只保存摘要、计数、模型、摘要绑定和脱敏结论，原始正文与事件只保留在本机私有归档

发布矩阵不得写入用户接受字段

### 6. 最终本地门槛

- Python 全量编译
- Skill `quick_validate`
- 基础合同和 Schema
- 动态确定性、语境和生命周期检查
- 前向案例分布与全局去重
- 精确补丁提交器
- 运行时 `compile`、`verify`、`repair`、`close`、`report`
- AEMP 内容充分性
- 代码同行对齐与 JSON 回退
- 216 项触发证据
- 24 项长上下文证据
- 生成物零差异
- `git diff --check`
- 全树隐私和凭据扫描
- README、账本、审核包和真实计数一致

### 7. 归档、发布和安装

终验前建立可恢复归档，保存所有引用、分支、reflog、stash、worktree、差异、未跟踪原件、私有闭环证据和安装前摘要

使用 `git bundle verify`、测试克隆、补丁预检和摘要复核证明归档可恢复

候选先普通推送并等待 Actions 全绿，重新读取远端 `main` 和保护状态后，使用观察到的旧提交租约执行精确 `--force-with-lease`

新 `main` 的 Actions 全绿后，先安装到同卷临时目录，比较远端树和安装树，运行 `quick_validate` 与 18 项安装后冒烟，再原子替换正式安装

候选 CI、`main` CI、安装或冒烟任何一项失败时，保留候选和归档，恢复旧安装并按精确租约回退，不进入清理

### 8. 最终清理

安装和冒烟全部成功后：

1. 归档旧主工作区的所有未提交内容
2. 不使用 `git reset --hard`
3. 安全恢复旧主工作区到最终 `main`
4. 清理失效 worktree 登记
5. 删除远端和本地所有非 `main` 分支
6. 验证本地和远端只剩 `main`
7. 验证 HEAD、工作树、生命周期、README、安装摘要和最终归档全部一致
