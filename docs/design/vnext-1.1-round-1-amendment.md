# vNext 1.1 首轮审核修正案

## 1. 修正效力

本修正案记录 2026-08-30 完成的 12 个候选锚点审核；原始权威计划保持不变，本文件只补充真实用户反馈已经确认的新约束

`CANDIDATE-01` 与 `CANDIDATE-02` 获得用户明确接受，因此转为首批金标；其余 10 个原始版本保留为拒绝案例，用于阻止同类问题复发

## 2. 首次术语解释

独立测试不继承其他案例已经解释过的术语；每个独立案例都必须重新证明首次解释能力

术语首次出现时按照以下顺序处理：

- 保留官方名称和大小写
- 括号只容纳正式英文全称或缩写
- 括号外说明定义、当前用途和实际影响
- 一句话过重时拆成相邻段落

`npm` 按照官方写法保持小写；npm 官方说明该名称不是 `Node Package Manager` 的缩写，因此正文写作 `npm 包管理器` 并自然解释其用途 [1]

## 3. 解释深度和段落边界

解释需要让零先验读者能够继续判断或操作；只给术语换一个近义词仍然不充分

冒号后出现两个以上独立项目时必须换行并缩进；列表项目内部再次出现并列内容时继续增加一级缩进

主题发生变化时另起一段；长度短不能成为合并不同主题的理由

## 4. 图表和代码

原图、原表或原始代码必须先于解释出现；内部覆盖账本记录所有有效元素，正文根据组件特点组织解释

图片解释同时覆盖外观、功能、连接、实际作用和证据边界；表格先统一定义列、行和值，再单独解释异常值和决定结论的关键数据格；代码说明保留原始代码，并补充语言、输入、关键语法、执行方法、可观察结果、副作用和验证边界

Mermaid 默认使用 `flowchart TD`；只有登记不可替代理由后才允许横向布局；每张图后继续解释节点关系、流程结果和证据边界

## 5. 边界说明

裸露的“不会修改”或“不能证明”只给出了否定结论；合格边界还需要说明形成原因、缺少的证据、实际影响和下一项核对方法
