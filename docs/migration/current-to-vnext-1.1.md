# 当前版本到 vNext 1.1 的迁移映射

## 1. 迁移原则

迁移只保留仍然服务于事实保真、来源追踪和确定性检查的内容；旧式禁词、固定句长、通用顺序和统一解释模板不直接迁入

## 2. 保留内容

| 现有能力 | vNext 位置 | 迁移原因 |
| --- | --- | --- |
| 事实、条件、否定和范围保护 | `constitution/` 与来源单元契约 | 这些信息决定原意，任何漂移都会改变结果 |
| 数字、路径和代码标识保护 | `registries/` 与 `validators/machine-final/` | 这些对象能够由代码进行确定性比较 |
| 用户偏好案例 | `evals/candidate/`、`evals/gold/` 与 `evals/rejected/` | 案例状态必须反映真实人工审核 |
| 图片、表格和代码的基础规范 | `profiles/components/` | 组件规则需要根据任务配置加载 |
| 确定性检查脚本经验 | 新验证器与精确提交器测试 | 复用能够机械证明的部分，停止声称代码可以证明完整语义 |

## 3. 降级内容

| 现有规则 | 新等级 | 迁移原因 |
| --- | --- | --- |
| 单词级机器味检测 | `MACHINE_CANDIDATE` | 单个词是否生硬取决于语境，不能直接阻断 |
| 固定句长阈值 | `ADVISORY` | 句长只能提示阅读负担，不能证明文本错误 |
| 普遍因果顺序 | `ADVISORY` | 时间、条件和比较类内容需要不同结构 |
| 统一术语解释模板 | 登记表加任务配置 | 不同术语和读者需要不同首次出现形式 |
| 正则自然度判定 | 候选提醒与人工金标 | 正则只能定位表面模式，不能证明自然度 |

## 4. 替换内容

| 旧入口 | vNext 替换 | 当前状态 |
| --- | --- | --- |
| 单轴写作任务 | 基础操作加解释增量 | 契约阶段 |
| 原文与解释混合成文 | 来源分层和支持映射 | 契约阶段 |
| 全文重写式修复 | 摘要绑定的精确补丁 | 最小实现阶段 |
| 模型生成案例直接计分 | `candidate`、`gold`、`rejected` 状态 | 等待首批人工审核 |
| 所有规则统一写成硬要求 | 四级规则 | 登记阶段 |

## 5. 不迁入内容

- 旧工作区未提交的上一代扩展
- 依赖外部 Agent 才能运行的质量流程
- 与写作无关的发布、账户、权限和安装回执架构
- 未经用户审核的模型偏好结论
