# 原文理解与来源登记

## 1. 目标

理解阶段把原文切成可追溯片段和最小语义单元；它不追求漂亮中文，只确认每项内容来自哪里、表达什么和必须保留什么

## 2. 处理顺序

第一步，按照段落、句子、列表项、表格单元格、图片元素或代码功能块建立 `SourceSpan`

第二步，把每个承担信息作用的内容拆成 `SourceAtom`；主体、动作、对象、否定、条件、范围、数量、因果和可能性分别保留

第三步，把用户新增事实登记为 `USER_SUPPLIED`；它不能被误写成原文内容

第四步，把必要背景登记为 `BackgroundAtom`；每项必须写明用途、来源和允许进入的段落

第五步，把推导结果登记为 `InferenceAtom`；每项必须列出支持单元、置信度和禁止升级成事实的边界

## 3. 歧义处理

原文存在多个会改变结果的解释时，保留全部候选并把状态设为 `unresolved`；系统不能选择语言最顺畅的解释，下一步进入一次性问答确认

## 4. 通过条件

- 每个有效原文片段已经处理
- 每个源语义单元具有原文位置
- 每个背景单元具有来源或明确知识性质
- 每个数字、日期、版本、路径和代码标识已经保护
- 每个否定、条件、范围和可能性单独保留
- 每个歧义已经解决或明确阻断
