# vNext 1.1 第二轮审核修正案

## 1. 修正效力

本修正案记录 2026-08-31 完成的 R2 人工审核与防过拟合决定；原始权威计划和首轮修正案继续有效，本文件只覆盖第二轮新增或修正的内容

`CANDIDATE-04-R2` 至 `CANDIDATE-12-R2` 获得用户明确接受，正文以精确摘要冻结；`CANDIDATE-03-R2` 因主语不明确和 npm 解释不完整转为版本化拒绝记录，并建立 `CANDIDATE-03-R3`

## 2. 主语明确性

独立动作、主体切换、代码注释和可能产生歧义的位置必须说明谁执行动作、谁产生结果

相邻内容保持同一主体且不存在歧义时允许自然省略；主语检查属于 `MACHINE_CANDIDATE`，程序只能核对 Agent 登记的承接关系，不能通过正则强迫每句话重复主体

## 3. 空行、段落和标点

不同主题之间保留一个空行；同一列表的相邻项目不插入空行；连续两个以上空行属于确定性错误

短停顿、紧密动作和 Mermaid 节点内部优先使用逗号；较长并列分句和对比关系可以使用分号；逗号与分号的选择不设置数量阈值，也不升级为通用硬门

中文正文继续禁用中文句号；逐字引文、代码和日志保持原样

## 4. 对齐与渲染能力

图片、表格、Mermaid 和题注默认请求居中；HTML、Word 和 PDF 可以记录精确对齐，GitHub 原生表格和 Mermaid 需要根据实际渲染器能力登记限制

系统必须区分“用户请求居中”和“渲染器能够保证居中”；渲染器无法精确控制时保留可访问结构，完成桌面与移动端检查，并说明不能保证的部分

原始 SVG 的元素重叠属于图片资产质量问题，不自动归入写作失败

## 5. 原始材料呈现

短篇逐字原文、用户原话和需要核对的证据文本使用引用块；代码与日志使用对应代码块；图片和表格保留原始对象；长篇原文建立独立小节

生成的结论、摘要和普通强调禁止使用引用块；命令、字段、标识符、路径和代码类型使用反引号

## 6. 审核快照

每个用户接受版本保存 `profile_revision_at_review` 与 `approved_snapshot_sha256`；后续偏好进入 `non_blocking_preferences`，不得反向修改已经审核的正文

拒绝记录允许使用版本化编号；新修订必须建立新的 Candidate，不能覆盖旧失败证据

## 7. 防过拟合验收

旧确定性集合增加 16 个正反例，并增加 12 个语境案例；语境案例全部设置 `automatic_decision=false`

正式泛化证据来自两轮各 20 个未见案例；每轮生成 Agent 只读取当前 Skill、原始请求和对应素材，每个答案只生成一次，生成前不能读取预期答案、怀疑问题或评分依据

每轮需要至少接受 18/20，同时事实、条件、范围、来源和原文遗漏硬错误为 0；第一轮没有通过以前禁止生成第二轮

## 8. 正式启用边界

在 `CANDIDATE-03-R3` 和两轮未见测试全部通过以前，`main` 保持冻结，本机正式 Skill 不安装候选版本，项目不能宣称已经解决泛化问题
