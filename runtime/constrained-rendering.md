# 受约束成文

## 1. 目标

受约束成文直接根据任务契约、内容骨架和用户配置生成目标风格正文；系统不先生成一个粗糙版本再进行多轮全文改写

## 2. 允许调整

- 中文措辞、句子长度和段落节奏
- 标题、列表和术语解释方式
- 正式程度和口语程度
- 图片、表格、代码和公式的呈现方式
- 当前用户配置中的标点和阅读习惯

## 3. 禁止调整

- 源语义单元
- 原文条件、否定、范围和结论强度
- 背景信息的来源类型
- 已确认的逻辑依赖
- 用户没有授权的新结论

## 4. 来源呈现

原文和补充说明可以通过就近解释、前置背景或独立补充说明自然结合；读者必须能够分辨哪些是原文主张，哪些是理解原文所需的外部背景或推断

任务合同要求同时展示原始材料时，按照材料类型选择呈现方式：

- 短篇逐字文本使用引用块
- 代码和日志使用对应语言的代码块
- 图片和表格保留原始对象
- 长篇原文进入独立原始材料小节

引用块只表示逐字来源或证据；生成结论、摘要和普通强调不得使用引用块

## 5. 主体与段落

独立动作、主体切换和可能产生歧义的位置明确主体；同一段落连续讨论一个明确主体时允许自然省略，禁止为了通过检查而机械重复主体

不同主题或块级结构之间使用一个空行；同一列表和嵌套列表内部保持连续，连续两个以上空行属于确定性错误；把行内内容转换为列表时，必须在同一局部补丁中补齐列表前后的必要空行，不能把新产生的块级错误留到下一轮

短停顿和紧密衔接使用逗号；分号只用于同一行紧凑并列或专业词说明；一旦内容构成多个独立项目就换行并按层级缩进

短单主题内容直接成文；多个独立内容区块按照任务合同选择 Markdown 标题层级；禁止使用冒号结尾的伪标题；自然完整句需要引出后续列表、引文或示例时使用冒号，这种语法作用不属于伪标题

同一行的复核编号、审计编号或人类可读票据号可以作为紧凑元数据直接引出对应正文，例如“复核编号 B23：抽查 18 张”；这类结构不承担分区作用，不是冒号伪标题，也不因包含编号自动要求行内代码格式

## 6. 媒介与居中

图片、表格、Mermaid 和题注默认共同居中；GitHub 图片使用居中 HTML 图片容器，表格使用可访问的居中 HTML 表格，Mermaid 保留原生代码块并使用独立居中 HTML 题注

GitHub 候选必须在 1280 像素与 390 像素、亮色与暗色主题中检查对象位置、题注位置和横向溢出；只有实际页面全部通过才能声明居中完成

## 7. 句子支持

最终正文中的每个有效句子建立 `SupportMap`；无法指向源语义、用户补充、背景来源、推断关系、组件解释或必要过渡的句子进入删除候选

代码采用注释路径时，每个代码块先计算最长可注释代码显示宽度 `L`；当前行显示宽度为 `W` 时，在代码后精确补 `L-W+1` 个空格再写注释标记，因此最长行也保留一个分隔空格，所有注释标记的 1 基列号固定为 `L+2`；对齐可以增加行宽，不能把注释移到下一行

两个以上可注释语句必须先把代码块正文通过标准输入交给 `runtime/align_inline_comments.py` 机械对齐，再对最终代码块运行同一脚本的 `--check`；只有检查返回 `PASS` 才能输出，不能依赖视觉估计；JSON 等不能合法添加注释的格式保留原文并使用可定位逐行解释，同行对齐登记为 `not_applicable`

## 8. 专业名词

独立阅读单元中的专业名词首次出现时说明正式中文、官方英文、正式缩写、中文定义、名称含义、当前作用和实际影响；翻译任务必须在对应源语义首次出现的位置使用正式中文并保留官方英文名称，不能先用泛称代替、再依靠后置术语表补救

官方形式具有最高优先级；`npm`、`Node.js`、`iOS`、`macOS` 和 `scikit-learn` 等名称不能为了统一外观而改写；`CI` 和 `HTTP` 等缩写保持登记形式；`npm` 不展开成 `Node.js Package Manager`

代码块、行内代码、网址、路径和逐字引用保持原始字符；这些内容不参加正文大小写修正

`core_terms`、主题关键词和普通操作短语不自动成为专业名词；登记表和来源都没有提供正式身份的普通任务标签使用自然中文解释，不创造英文形式；确属专业名词但官方写法仍无法确认时停止生成该形式并返回 `REVIEW_REQUIRED`

## 9. 排比与多轮要求

两个以上承担相同作用的定义、步骤、比较对象、事实、原因或动作换行并缩进；嵌套并列继续增加一级缩进；压缩任务减少重复措辞，同时保留主题边界和必要换行

一句说明同时作用于多个嵌套子项时，把共同说明写在父项中，再列出子项；禁止把共同说明放在最后一个子项之后并使用与子项相同的缩进，避免它在结构上只附着到最后一个子项

篇幅极短且紧密关联的审计事实可以登记为 `compact_inline` 并使用分号留在同一行；`COMPRESS + NONE` 已经从原文保留未知或未检查范围时，不额外创造影响判断、建议或下一项核对动作

证据边界默认只进入内部验证包；只有限制影响读者结论、操作或安全时才自然说明；禁止直接输出内部字段名称

追加要求替换旧要求后，最终正文只保留当前有效内容；只有用户要求变更历史、撤销说明，或者法律、审计与证据核对需要时，才保留失效要求
